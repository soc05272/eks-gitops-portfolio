# ADR-001: 배포 도구로 ArgoCD를 선택한 이유

- 상태: 승인
- 날짜: 2026-07-24

## 배경

CI(빌드)는 GitHub Actions로 확정. CD(배포)를 어떻게 할지 결정 필요.

## 선택지

1. **GitHub Actions에서 직접 `kubectl apply`** — 파이프라인 하나로 단순하지만, 클러스터 자격증명을 CI에 심어야 하고(push 방식), 배포된 상태와 Git의 선언 상태가 어긋나도 감지할 방법이 없다.
2. **ArgoCD (GitOps, pull 방식)** — 클러스터 내부의 ArgoCD가 매니페스트 repo를 감시하고 스스로 동기화. 자격증명이 클러스터 밖으로 나가지 않고, drift 감지·자동 복구·롤백(Git revert)이 가능하다.

## 결정

**ArgoCD 선택.**

- Git이 단일 진실 공급원(single source of truth)이 되어, 온프레미스 운영 시절 겪었던 "지금 서버에 뭐가 배포돼 있는지 아무도 모르는" 문제를 구조적으로 해결
- 앱 repo(코드/CI)와 매니페스트 repo(배포 상태)를 분리하여 권한과 이력을 명확히 구분

## 트레이드오프

- 컴포넌트가 하나 늘어나 클러스터 리소스를 추가로 사용
- 매니페스트 repo 분리로 초기 설정이 다소 복잡 → 소규모 프로젝트에서는 과할 수 있으나, GitOps 패턴 자체를 검증하는 것이 이 프로젝트의 목적이므로 감수
