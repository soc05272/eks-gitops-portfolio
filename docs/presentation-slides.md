## 슬라이드 4 — 아키텍처

[제목]
사람의 개입은 git push 하나

[다이어그램 텍스트]
git push → GitHub Actions(OIDC 키리스 인증) → ECR
→ 매니페스트 repo 자동 커밋 → ArgoCD auto-sync → 무중단 롤링 배포

VPC (2개 가용영역)
· Public 서브넷 — ALB · NAT
· Private 서브넷 — EKS 노드(Spot ×2): 앱 파드 · ArgoCD · Prometheus/Grafana
· DB 서브넷 — RDS PostgreSQL

사용자 → ALB → 파드 → RDS / Claude API

[포인트 3개]
· 액세스 키 없는 CI 인증 (OIDC)
· 파드 단위 최소 권한 (IRSA 4종)
· 상태(stateful)와 무상태(stateless)의 네트워크 계층 분리

〔디자인〕 이 장이 가장 공들일 장. 배포 흐름(가로)과 VPC(세로 박스)를 분리해 그리기

## 슬라이드 5 — 의사결정 (ADR)

[제목]
선택마다 트레이드오프를 기록했습니다

[본문 — 3행 비교]
ArgoCD (pull)   vs CI 직접 배포(push) → 자격증명이 클러스터 밖으로 안 나감 · drift 자동 복구
RDS             vs 클러스터 내 DB     → 백업·패치·장애조치를 관리형으로, 앱과 DB 수명주기 분리
단일 NAT        vs AZ별 NAT           → 포트폴리오 환경에서 월 $40 절감, SPOF는 문서화하고 수용

[하단]
"과하지 않게" — 서비스 메시 · 멀티클러스터 · Karpenter는 규모 대비 과잉으로 판단해 제외

〔디자인〕 "선택 vs 대안 → 이유" 3행 표. ADR 문서가 repo에 있음을 각주로

## 슬라이드 7 — GitOps 파이프라인

[제목]
push부터 배포까지 자동 — 롤백은 git revert 한 번

[다이어그램 텍스트]
① git push (버전 0.2.1)
② GitHub Actions — OIDC 인증 → 이미지 빌드 → ECR 푸시
③ 매니페스트 repo에 태그 자동 커밋 (kustomize edit)
④ ArgoCD가 감지 → 무중단 롤링 배포
⑤ 인터넷에서 확인: {"version": "0.2.1"}

[본문]
· 앱 repo(공개)와 매니페스트 repo(비공개) 분리 — Git이 배포 상태의 단일 진실 공급원
· 수동 배포와 섞여도 ArgoCD가 drift를 감지하고 Git 상태로 복원

〔디자인〕 ①~⑤ 세로 타임라인. ⑤는 실제 curl 응답 캡처로 대체 가능

## 슬라이드 9 — 트러블슈팅 ① 조용한 실패

[제목]
38분간 아무 에러도 없이 실패하고 있었다

[본문 — 3단]
증상   | EKS 노드그룹 CREATE_FAILED — 그런데 상태 API(health.issues)는 끝까지 비어 있음
진단   | "인스턴스가 떴는가?"로 문제를 절반으로 쪼갬 → 기동 자체가 거부됨
       | 원인이 실제로 적히는 곳은 ASG 활동 로그였다
원인   | AWS Free Plan 계정의 인스턴스 타입 제약 (코드 문제가 아니라 계정 정책)

[해결]
우회(타입 변경) 대신 근본 해결(Paid 전환) — 코드 한 줄 안 바꾸고 재시도 성공

[배운 점]
실패는 "원인이 기록되는 곳"이 따로 있다 — API가 조용하다고 정상이 아니다

〔디자인〕 증상/진단/원인 3단 박스. 트러블슈팅 3장(9~11)은 같은 레이아웃으로 통일

## 슬라이드 10 — 트러블슈팅 ② 보이지 않는 불일치

[제목]
추측을 멈추고, 상대가 실제 보낸 값을 봤다

[본문 — 3단]
증상   | CI의 AWS 인증 실패 — 에러는 "Not authorized" 한 줄뿐
진단   | 가설 2개(전파 지연 · 정책 연산자)를 세우고 검증으로 기각
       | CloudTrail에는 GitHub가 실제 제시한 값이 남아 있었다
원인   | GitHub가 sub 클레임 형식을 변경(@계정ID·@저장소ID 추가) — 커뮤니티 모듈은 구형식

[해결]
Role을 직접 정의하고 ID까지 고정 — 계정명 탈취·재생성 공격까지 막히는 부수효과

[배운 점]
신뢰 정책은 "내가 기대하는 값"이 아니라 "상대가 보내는 값"과 일치해야 한다

〔디자인〕 실제 sub 두 줄(기대 vs 실제)을 코드 블록으로 대비시키면 효과적

## 슬라이드 11 — 트러블슈팅 ③ 재발과 절차 개선

[제목]
같은 실수 두 번째 — "조심"이 아니라 절차를 바꿨다

[본문 — 타임라인]
1차 사고 | 토큰 복사 시 개행 혼입 → 인증 실패
대응     | 클립보드에서 직접 읽는 방식(pbpaste) 도입
2차 사고 | 명령어를 복사하는 순간 클립보드의 토큰이 덮임 → 명령어가 비밀번호로 등록
대응     | 클립보드를 데이터 경로에서 제거 — 화면 비표시 프롬프트로 절차 교체

[배운 점]
· 재발은 사람의 부주의가 아니라 프로세스의 결함 신호
· 비밀값 오류는 값을 노출하지 않고 길이·접두사만으로 진단 가능

〔디자인〕 1차→대응→2차→대응 세로 타임라인. 면접에서 태도를 보여주는 장
